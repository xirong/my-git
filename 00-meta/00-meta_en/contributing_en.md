# Contributing

English | [中文](../contributing.md)

Thank you for your willingness to help maintain this repository.

The new direction for this repository is a practical Git / GitHub handbook for modern engineering teams. We welcome contributions of real-world problems, team practices, incident recovery experiences, AI programming workflows, and reusable templates.

## Recommended Ways to Contribute

1. Open an Issue first to describe the problem you want to address.
2. Specify who the target audience is.
3. Explain what real-world problem this content solves.
4. Keep changes focused when submitting a PR.

## Content Requirements

- Prioritize contributing practical engineering judgment, not just links.
- Commands must be presented so that readers understand the risks.
- Dangerous operations must be preceded by pre-checks.
- For GitHub features, try to reference official documentation.
- Template-type content should be directly ready for copy-pasting.

## PR Requirements

- Each PR should ideally address only one topic.
- Place new articles in the corresponding directory.
- New content must follow the [Content Style Guide](content-style-guide_en.md).
- When modifying legacy articles, try to keep historical links functional.
