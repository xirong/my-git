# 团队协作

这个目录帮助团队选择合适的 Git 工作流，并把分支、PR、Review、发布节奏串成稳定协作方式。

## 先读什么

| 你要解决的问题 | 建议阅读 |
| --- | --- |
| 不知道团队该选哪种工作流 | [团队 Git 工作流指南](team-git-workflow-guide.md) |
| 小团队、高频 Web 服务如何协作 | [GitHub Flow](github-flow.md) |
| 发布频率和合入频率不同 | [GitLab Flow](gitlab-flow.md) |
| 想围绕主干高频集成 | [Trunk-Based Development](trunk-based-development.md) |
| 客户端、SDK、多版本交付 | [Gitflow](gitflow.md) |
| 外部贡献者很多 | [Fork and Pull Request Workflow](fork-and-pr-workflow.md) |

## PR 和 Review

- [Pull Request 最佳实践](pull-request-best-practices.md)
- [Code Review 最佳实践](code-review-best-practices.md)

如果 PR 太大、Review 太慢，先看 PR 最佳实践。
如果团队经常陷入低价值评论、owner 不清、Review 质量不稳定，先看 Code Review 最佳实践。
